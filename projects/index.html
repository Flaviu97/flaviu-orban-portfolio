Splunk SIEM Lab – Brute Force Detection

Simulated brute-force attack from Kali Linux against a Windows host. Detected using Splunk SIEM through EventCode 4625 and analysed via dashboards.

Designed and implemented a SIEM-based detection workflow to identify brute-force login attempts using Windows Security logs.

Lab Overview

  • Deployed Splunk on Ubuntu Server
  • Configured Windows log forwarding using Universal Forwarder
  • Simulated brute-force attacks from Kali Linux
  • Generated failed login events using Windows EventCode 4625

Detection Logic

Analysis & Reasoning

  • Repeated failed logins indicate potential brute-force activity
  • Single source IP suggests targeted attack rather than user error
  • High frequency increases the likelihood of malicious behaviour

Identified suspicious authentication patterns by analysing repeated failed login attempts from a single source IP. 

index=* sourcetype=WinEventLog:Security EventCode=4625
| stats count by Source_Network_Address, Account_Name
| sort -count

Investigation Process

Alert Triage

  • Severity: Medium → High based on frequency
  • False positive check: compare with normal user login behaviour
  • Decision: escalate for further investigation
  • Detected multiple failed login attempts within a short time frame
  • Identified attacker IP address from Kali Linux
  • Correlated events with targeted user accounts
  • Confirmed brute-force behaviour based on repetition patterns

Outcome

Response Actions

  • Block attacker IP at firewall
  • Reset affected user credentials
  • Enable account lockout policies
  • Monitor for repeated attempts
  • Successfully detected simulated brute-force activity
  • Built dashboards to visualise attacker IPs and targeted accounts
  • Developed practical understanding of SOC alert triage workflows
